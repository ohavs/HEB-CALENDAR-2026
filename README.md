# לוח שנה עברי

אפליקציית לוח שנה עברי: כל החגים והמועדים, זמני כניסת ויציאת שבת מדויקים לפי מקום,
אירועים אישיים עם תזכורות, מצב לילה, וסנכרון לענן. בנויה כ-PWA, מיושרת לימין,
ונארזת גם כאפליקציית אנדרואיד.

## מה יש באפליקציה

**לוח השנה**
- שלוש תצוגות: **חודש** (רשת נקייה, שהמועדים והאירועים כתובים על גבי הימים
  עצמם), **שבוע** (ציר שעות, עם שורה נפרדת למה שאין לו שעה וקו לשעה הנוכחית),
  ו**סדר יום** (רשימה רציפה שבה יום בלי כלום פשוט לא מופיע).
- תאריך עברי בכל תא (ניתן לכיבוי), ושם החודש העברי בכותרת.
- מעבר בין חודשים בהחלקה, עם אנימציית מעבר חלקה.
- לחיצה על יום בוחרת אותו; לחיצה נוספת על היום הנבחר פותחת **תצוגת יום מורחבת**
  עם המועדים, זמני השבת, זמני היום (עלות השחר עד צאת הכוכבים) והאירועים.
- תצוגת שנה בלחיצה על שם החודש.
- חיפוש באירועים ובמועדים, עם נרמול עברי: ניקוד, גרשיים, אותיות סופיות ומקף
  לא מכשילים אותו, ו"תשפז" מוצא את "תשפ״ז".
- הגדרת צפיפות: מרווח מראה כותרות, קומפקטי מראה נקודות צבע ומפנה מקום בתא.
- ניווט מקלדת מלא: חיצים בין ימים, Home/End לקצות השבוע, PageUp/PageDown
  לחודש, ו-Alt+חיצים להזזת אירוע - החלופה לגרירה.

**אירועים**
- יצירה ועריכה בחלונית תחתונה, עם צבע, מקום, שעות, חזרתיות והערות.
- **העברת אירוע בין ימים בלחיצה ארוכה וגרירה** (כמו בסמסונג): רטט קצר,
  צל שנגרר עם האצבע, הדגשת יום היעד, ומעבר חודש אם גוררים אל קצה המסך.
  אחרי השחרור מוצגת הודעה עם אפשרות ביטול.
- חזרתיות: שבועית, חודשית, שנתית לועזית, ושנתית **לפי התאריך העברי**
  (מטפל נכון גם באדר א׳/ב׳ בשנה מעוברת).
- **חריגים למופע יחיד**: אפשר לבטל, להזיז או לשנות מופע אחד בסדרה בלי לגעת
  בשאר. כל פעולה על מופע בסדרה שואלת "המופע הזה או כל הסדרה?".
- **אירועים רב־יומיים**: חופשה או טיול נפרשים כפס רציף על פני הימים.

**שבת וחגים**
- טאב נפרד עם זמני הכניסה והיציאה של השבת או החג הקרוב, ורשימת השבועות הבאים.
- בחירת עיר מתוך ~80 ערים בישראל ובעולם, או איתור אוטומטי לפי מיקום המכשיר.
- הדלקת נרות לפי דקות לפני השקיעה, והבדלה לפי מעלות צאת הכוכבים או לפי דקות.

**תזכורות**
- לפני כניסת שבת/חג, ביציאת שבת/חג, בערב שלפני מועד או צום, ולאירועים אישיים.
- כל אחת מהן ניתנת להגדרה בנפרד (מתי, כמה זמן לפני).

**נוסף**
- מצב לילה מלא (בהיר / כהה / לפי המערכת), בלי הבהוב בטעינה.
- PWA: התקנה במסך הבית ועבודה גם בלי אינטרנט.
- התחברות עם גוגל וסנכרון האירועים וההגדרות בין מכשירים, עם זיהוי התנגשויות:
  שני מכשירים שערכו את אותו אירוע במצב לא־מקוון - הגרסה שהפסידה נשמרת ומוצגת
  להשוואה במקום להיעלם.
- **ייצוא וייבוא ICS**: גיבוי שלא תלוי בחשבון, ודרך להכניס לוח קיים מגוגל.
- חיווי ניתוק שאומר שהנתונים נשמרו במכשיר ויסונכרנו כשהרשת תחזור.

## דיוק הזמנים ושעון קיץ/חורף

כל חישובי הזמן מתבססים על **מזהה אזור זמן IANA** של העיר (למשל `Asia/Jerusalem`),
ולא על היסט קבוע. המשמעות: המעבר בין שעון קיץ לשעון חורף מטופל אוטומטית ונכון
לכל תאריך בעבר ובעתיד, גם אם כללי השעון ישתנו. חישובי הלוח העברי, החגים,
הפרשות והזמנים ההלכתיים נעשים בעזרת [`@hebcal/core`](https://github.com/hebcal/hebcal-es6).

לוח החגים נקבע לפי העיר: עיר בישראל מקבלת את לוח החגים הישראלי (יום טוב אחד),
ועיר בחו״ל מקבלת את לוח הגלויות (יום טוב שני).

## סודות וקונפיגורציה

- **אין סודות בקוד ואין סודות ב-git.** קונפיג ה-Firebase נקרא ממשתני סביבה
  (`import.meta.env.VITE_*`) מתוך `.env.local`, שנמצא ב-`.gitignore`.
  `.env.example` מכיל רק שמות משתנים, בלי ערכים.
- מפתחות של אפליקציית web ב-Firebase הם **מזהים ציבוריים** מעצם טיבם: הם נשלחים
  לדפדפן של כל מבקר. ההגנה על הנתונים אינה בהסתרת המפתח אלא ב-`firestore.rules`
  (כל משתמש ניגש רק ל-`users/{uid}` שלו) וב-Authorized domains של Firebase Auth.
- **טוקן ה-CI** של Firebase (`firebase login:ci`) הוא סוד אמיתי עם הרשאות פרסום
  לכל חשבון ה-Firebase. הוא לא נשמר בריפו. אם צריך פרסום אוטומטי, שומרים אותו
  כ-GitHub Secret בשם `FIREBASE_TOKEN` ומשתמשים בו רק מתוך ה-workflow.
  אם טוקן כזה נחשף אי פעם - יש לבטל אותו ב-<https://myaccount.google.com/permissions>.

### הגדרת Firebase

1. ב-Firebase Console → Authentication → Sign-in method: להפעיל **Google**.
2. Authentication → Settings → Authorized domains: להוסיף את הדומיין של האפליקציה.
3. Firestore: ליצור מסד, ולפרסם את הכללים:
   ```bash
   npx firebase deploy --only firestore:rules
   ```
4. פרסום האפליקציה:
   ```bash
   npm run build
   npx firebase deploy --only hosting
   ```

## מקום של אירוע

בחירת המקום נשענת על שלוש שכבות, לפי מה שסביר שהמשתמש יבחר: **המקומות
השמורים שלו** (בית, עבודה - הוא כבר טרח להגדיר אותם), **מקומות שכתב
באירועים קודמים** ("בית הכנסת", "אצל סבתא"), ו**ערים** מהרשימה המובנית.
טקסט חופשי נשאר תמיד זמין, כי "אצל סבתא" הוא מקום לגיטימי שאין לו כתובת.

כשנבחר מקום שמור נשמר גם מזהה שלו (`placeId`) ולא רק הכיתוב, כדי ששינוי
שם של מקום שמור לא ינתק ממנו את כל האירועים.

**הכול מקומי.** אין קריאת רשת, אין מפתח API, ומה שהמשתמש מקליד לא יוצא
מהמכשיר.

## מקומות שמורים

מקום שמור ("בית", "עבודה") נושא נקודת ציון ורדיוס, ומשמש להתראות הגעה
ויציאה. יש שלוש דרכים לקבוע את הנקודה, ורק אחת מהן דורשת להיות שם:

1. **המיקום הנוכחי** - כשבמקרה עומדים במקום.
2. **הדבקת נקודה ממפות** - המסלול המעשי להגדיר את הבית מהספה: פותחים
   מפות, לוחצים לחיצה ארוכה על הנקודה, ומעתיקים. כל מה שיוצא משם
   מתפענח מקומית, בלי שום קריאת רשת:

   ```
   31.7683, 35.2137                       העתקה ישירה
   31°46'05.9"N 35°12'49.3"E              לוח המידע בדסקטופ
   google.com/maps/place/…/@31.76,35.21   שיתוף של מקום
   google.com/maps?q=31.7683,35.2137      קישור חיפוש
   maps.apple.com/?ll=…                   מפות של אפל
   waze.com/ul?ll=…                       ווייז
   geo:31.7683,35.2137                    כוונה של אנדרואיד
   ```

   קישור **מקוצר** (`maps.app.goo.gl`) לא נתמך: אי אפשר לדעת לאן הוא
   מצביע בלי לפתוח אותו, וזו קריאה שהדפדפן חוסם ב-CORS ממילא. האפליקציה
   מזהה את המקרה ואומרת מה לעשות במקום להיכשל בשקט.
3. **בחירת עיר כנקודת פתיחה** - מרכז העיר, לכוונון אחר כך. הרדיוס עולה
   אוטומטית לקילומטר, כי מרכז עיר אינו נקודה מדויקת.

אחרי שנקבעה נקודה יש קישור "פתיחה במפות" לאימות שהיא באמת במקום הנכון.

### למה אין חיפוש כתובות חופשי

הדבקת נקודה ממפות מכסה את הצורך המעשי, אבל היא לא חיפוש: אי אפשר להקליד
"רחוב הרצל 5, תל אביב" ולקבל נקודה. זה דורש שירות גיאוקודינג חיצוני,
והאפשרויות הן:

| שירות | מפתח | עלות | איכות בישראל |
| --- | --- | --- | --- |
| Google Places | נדרש, עם חיוב מופעל | חינם עד מכסה, אחר כך לפי קריאה | הטובה ביותר, כולל שמות עסקים |
| Nominatim (OSM) | לא נדרש | חינם | סבירה לכתובות, חלשה לשמות עסקים. מדיניות השימוש מגבילה קצב ודורשת ייחוס |
| Photon (Komoot) | לא נדרש | חינם | דומה ל-Nominatim, מתוכנן להשלמה אוטומטית |

מעבר לעלות, לכל אחת מהן יש מחיר אחד משותף: **כל תו שהמשתמש מקליד בשדה
המקום נשלח לשרת של צד שלישי.** באפליקציה שכל השאר בה עובד מקומית, זו
החלטה שצריך לקבל במפורש ולא בדרך אגב.

לכן ההחלטה נדחתה בכוונה. השכבות הקיימות מכסות את רוב השימוש האמיתי בלוח
עברי - בית, עבודה, בית כנסת, עיר - וכשתידרש הרחבה, נקודת החיבור היחידה
היא `suggestLocations()` ב-`src/lib/eventLocations.ts`.

## תזכורות: המגבלה של PWA

בדפדפן אין דרך מובטחת להעיר אפליקציה סגורה בלי push server. לכן התזכורות עובדות
בשתי שכבות:

1. **כשהאפליקציה פתוחה** - טיימרים בדף מציגים כל תזכורת בזמנה.
2. **כשהיא סגורה** - ה-service worker מציג תזכורות שהגיע זמנן, דרך
   Periodic Background Sync (נתמך בכרום באנדרואיד, לאפליקציה מותקנת).

כל חישוב התזכורות מרוכז בפונקציה טהורה אחת, `buildReminders()` ב-`src/lib/notifications.ts`.
במעבר לאנדרואיד מחליפים רק את שכבת התצוגה שמתחתיה בהתראות מקומיות של המערכת,
וכל הלוגיקה נשארת.

## אפליקציית אנדרואיד

האפליקציה נארזת ל-APK דרך Capacitor. ה-WebView טוען את אותו `dist` שהאתר
טוען, ולכן אין גרסה שנייה של הקוד: מה שנבדק בדפדפן תקף גם באפליקציה.

התפר היחיד הוא `src/lib/native.ts`. אין בו ייבוא סטטי של אף פלאגין -
`isNative()` בודק את הגשר שקפסיטור מזריק ל-window, וכל פלאגין נטען
ב-import דינמי רק אחרי תשובה חיובית. בדפדפן ובבדיקות אף אחד מהם לא נטען.

| מה | בדפדפן | באנדרואיד |
|---|---|---|
| וידג׳טים | אין | שלושה: לוח, תזכורות וזמני שבת |
| עדכונים | רענון הדף | חבילת web מוחלפת בתוך האפליקציה; APK רק כשהשתנה משהו נייטיבי |
| תזכורות | טיימרים בדף + service worker | התראות מקומיות של המערכת, מגיעות גם כשהאפליקציה סגורה |
| מיקום | `navigator.geolocation` | `@capacitor/geolocation`, שמבקש את ההרשאה בעצמו |
| התחברות | `signInWithPopup` | Credential Manager - גוגל חוסמת OAuth בתוך WebView |
| כפתור החזרה | היסטוריית הדפדפן | אותה היסטוריה בדיוק (`src/lib/overlayHistory.ts`) |

חישוב התזכורות, מנוע הלוח והגדר הגאוגרפית עוברים כמות שהם: `src/lib` אינו
מייבא מ-`src/components`, ולכן אין שם דבר שתלוי בדפדפן.

### בנייה

הבנייה רצה ב-GitHub Actions, על ראנר שכבר כולל את ה-Android SDK - אין צורך
ב-Android Studio. כל דחיפה לענף בונה APK ומפרסמת אותו לשחרור
`android-latest`, שהוא קישור ההורדה היציב לטלפון.

```bash
npm run icons:android   # אייקונים, אייקון התראה ומסך פתיחה מאותו לוגו
npm run android:sync    # build + npx cap sync android
```

כל ריצה מפרסמת שני תוצרים: APK להתקנה, וחבילת web לעדכון חי. האפליקציה
בוחרת ביניהם לפי טביעת הקוד הנייטיבי - הקומיט האחרון שנגע ב-`android/`,
ב-`package-lock.json` או ב-`capacitor.config.ts`.

סודות שהבנייה קוראת (Settings → Secrets and variables → Actions):

| סוד | בשביל מה | חסר? |
|---|---|---|
| `ANDROID_KEYSTORE_BASE64` | מפתח החתימה הקבוע | נחתם במפתח דיבאג, ואי אפשר לעדכן התקנה קיימת |
| `ANDROID_KEYSTORE_PASSWORD` | הסיסמה שלו | כנ״ל |
| `VITE_GOOGLE_WEB_CLIENT_ID` | מזהה הלקוח של גוגל (web) | האפליקציה עובדת מקומית, בלי התחברות וסנכרון |

מפתח החתימה לעולם אינו במאגר. ה-CI כותב אותו לקובץ זמני מחוץ לעץ העבודה.
מזהי הלקוח של גוגל, לעומת זאת, אינם סודות - הם מזהים ציבוריים, בדיוק כמו
מפתחות ה-web של Firebase.

### מה עוד אפשר

וידג׳טים: הנתונים מתקבלים מ-`buildDay()` ומ-`upcomingShabbatot()` - אותן
פונקציות שהאפליקציה עצמה משתמשת בהן.
